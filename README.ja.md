## 卒業プロジェクト提出版（2025-12-20）

### 1.　前処理パイプライン——`preprocessing/beauty_preprocess.ipynb`

Google　Colabで作成した30セルのノートブックです。商品メタデータとレビューを整形し、推薦にそのまま使える商品単位のスコアテーブルを作ります。

```
HFから読み込み → 事前フィルタ → 型の正規化 → raw_textの統合・整形
→ 属性オントロジー＋ルール抽出 → 信頼度調整 → レビュー指標の計算 → 結合 → CSV出力
```

| 段階 | 結果（提出版ノートブックの出力による） |
|---|---|
| 元データの規模 | メタデータ112,590件／レビュー701,528件 |
| 使用範囲 | メタデータ先頭15,045件／レビュー先頭12,358件（Colabのメモリ制約のため先頭から切り出し） |
| 事前フィルタ | 15,045→11,307件（3,738件、24.8%を除去） |
| 属性抽出 | brand、product_type、target_audience、volume_ml、scent、price_numの6属性を定義 |
| target_audienceの改善 | hard　pass　10.6%→17.8%（1,200→2,007件） |
| 最終出力 | `beauty_item_scoring_all.csv`　11,307行 |

#### 前処理の判断根拠

| 判断 | 理由 | 実装 |
|---|---|---|
| 許可／除外キーワードによる事前フィルタ | All_Beautyにタトゥー機材や工具など、美容商品の推薦対象ではない品目が混在している（除去例：タトゥーマシン用プランジャーバー） | 許可語を1つ以上含み、かつ除外語（tattoo、cartridge、needleなど）を含まない |
| レザーコンディショナーの文脈ルール | 「conditioner」はヘア製品と革製品ケアの両方で使われる | 「leather　conditioner」があり、hair／scalpの文脈がなければ除外**（提出版では適用されていない。下記の制約を参照）** |
| 情報源ごとの重み | 構造化されたフィールドほど値が正確 | details　1.00＞feature　0.85＞title　0.75＞description　0.60 |
| 属性ごとのhard閾値 | 属性ごとに誤抽出のリスクが異なる | brand　0.80、product_type　0.75、target_audience　0.70、scent　0.75、volume_ml　0.65、price_num　0.90 |
| 合意ボーナス | 複数の情報源で同じ値が出れば信頼度が高い | 2情報源で＋0.15、3情報源以上で＋0.20（上限1.0） |
| detailsの直接パース＋fallback | 本文のキーワードだけではtarget_audienceをほとんど拾えない | detailsのSkin　Type／Hair　Typeなどのキーを直接読む→hard　pass　10.6%→17.8% |
| レビュー指標の補正 | レビュー1〜2件の商品が平均評価の並び順を歪める | ベイズ平均（α=10、μ=4.081）、ウィルソン下限（95%、星4以上を肯定）、log1p人気度、参考になった数、データ内の相対的な新しさを0.50／0.20／0.15／0.10／0.05で加重和 |

### 2.　推薦アプリ——`app/app_sparse_final.py`（チームメンバー作成）

商品×属性の感情スコア疎行列を使い、コサイン類似度で推薦するStreamlitアプリです。

```
基準商品の選択 → 属性の感情値を修正・追加・削除 → L2正規化 → コサイン類似度top-K → CSVダウンロード
```

- 入力行列：50,000商品×9,976属性、値のあるセルは426,145個（1商品あたり平均8.5個）、値の範囲は-0.99〜1.00
- 行列はチームメンバーがspaCy（構文解析）とVADER（感情スコア）で作成しました。**生成コードはこのリポジトリに含まれていません。**

## 既知の制約（提出版）

提出後に見直して見つけた問題です。数値はすべて提出版ノートブックの出力または入力ファイルから直接確認しました。

**前処理**

- **レビューの大半が商品と結び付いていません。** メタデータとレビューをそれぞれ先頭から切り出したため、レビュー12,358件のうち残った商品に結び付いたのは1,424件です。レビューがある商品は967件（8.6%）です。出力の「review_signalカバレッジ100%」は、レビューのない商品を0で埋めた結果です。→修正済み[`554d417`](https://github.com/1220auto/review-attribute-mining/commit/554d417)
- **6属性のうち2属性が最終CSVで空です。** brandは11,307件すべてUnknown、volume_mlは0%です。price_numは18.3%（2,072件）のみ埋まっています。
- **レザーコンディショナーのルールが適用されていません。** Cell　4で`keep_mask`を再計算しましたが、`meta_df`に再適用していません。同じセルで除外語に追加した「leather」なども、除外判定が終わった後なので効果がありません。そのため「Howard　LC0008　Leather　Conditioner」（B01CUPMQZE）が最終CSVに残っています。→修正済み[`1a6e42f`](https://github.com/1220auto/review-attribute-mining/commit/1a6e42f)
- **キーワードを部分文字列で比較しています。** 除外語「vice」が「device」「service」にも一致し、許可語「oil」が「toilet」にも一致します。→修正済み[`a52d20a`](https://github.com/1220auto/review-attribute-mining/commit/a52d20a)。再実行の結果、判定が変わった商品は405件でした（下表）。
- カテゴリ文字列が空のため、カテゴリによる許可ルールは一度も一致しませんでした（0.0%）。フィルタはテキスト一致のみで動作しました。
- Colab専用パス（`/content/`）を使っており、セルの実行順序に依存しています。→パスは修正済み[`ac22c9b`](https://github.com/1220auto/review-attribute-mining/commit/ac22c9b)
- 前段セルの確認を内包表記の中の`locals()`で行っているため、Python　3.13環境（現在のColab）では最初の実行で停止します。→修正済み[`13092ca`](https://github.com/1220auto/review-attribute-mining/commit/13092ca)

**推薦アプリ**

- 9,976属性のうち2,561属性は値が1つもない列です。
- 上位の属性を一般語が占めています（partyが8,790商品に出現し、cake、ingredient、topper、birthdayが続く）。数字を含む属性（「100ml」「1st」「00」など）は544個ありますが、全体の値の0.21%で、推薦属性リストの上位150個には含まれていません。
- サイドバーにデバッグ用のディレクトリ一覧出力が残っています。

## 実行方法

**前処理ノートブック**：Google　Colabで開き、上のセルから順番に実行します。データはノートブックがHugging　Faceから直接取得します。

**推薦アプリ**：入力ファイル4つを`app/`に置いて実行します。ファイルの説明は[data/README.md](data/README.md)にあります。行列ファイルはこのリポジトリでは再生成できません。

```bash
pip install streamlit numpy pandas scipy scikit-learn
cd app
streamlit run app_sparse_final.py
```
